## Changed approach

Replace the repeated procedural kernel with **ImageGen-authored feather artwork**, then map and derive standard PBR detail in the editable source package. First establish recognizable feather groups: small crown feathers, elongated overlapping back faces with open partial edges, larger nested rump coverts, and a few overlapping flipper groups. Integrate the short tail visually into the rump rather than tracing its triangular boundary. Preserve the corrected feet.

Generated artwork is a source asset, not an engine render or evidence of success. Keep its prompt, original output, processing recipe and hashes. Review mapped coverage and feather scale at the fixed 304px reference height before preparing a new export. Derive restrained tangent-space normal and matte roughness detail from the authored design; do not bake course-specific lighting or alter game lighting to improve the comparison.

The first authored artwork solved faintness but retained overly regular rows. The next source edit uses the unchanged reference to establish varied tapered, interlocking feather clusters, broken partial edges and integrated rump/tail flow. Preserve the first output and edit prompt as provenance. Changing generation tools does not relax the same actual-pixel acceptance gate.

Keep the existing strict surface contract: unchanged V9 triangle positions/normals, UV seams explicitly accounted for, one standard material, embedded sRGB base color plus linear normal and metallic/roughness maps, zero metallic channel, imported mipmaps, and exact source/imported-pixel hashes. Gameplay and rear detail must use the same imported instance/material. Keep 1024px maps and the current export budget unless a separate explicit decision changes them.

A new source package must pass local source/import checks, freeze, then receive one complete final desktop/mobile capture set. Compare unannotated actual RGB with V9 and the unchanged reference; use overlays as supporting geometry evidence. Assess feather faces/overlap, regional scale, flipper and rump/tail integration in actual pixels. A static capture does not establish temporal shimmer or animation performance. The owner decides surface approval; front/podium, rigging and shipping remain later gates.
